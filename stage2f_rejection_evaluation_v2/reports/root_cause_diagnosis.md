# Stage 2F: diagnosis and minimal R2 candidate

Date: 2026-11-07. Development analysis, not an independent test or a new R2 performance evaluation.

## Inputs and scope

Discovered actual directories under `metrics`: `20261106_204802_280_R0`, `20261106_204802_280_R1`, and `20261106_204802_280_raw`. Their completed artifacts, hashes, raw identities, dataset coverage and shared lineage were verified. All 2,800 saved observations / 700 development parents were compared. All 896 R1 invalid ACCEPT cases and all reviews were included. No inference was executed. Dataset metadata was selected with the existing development-only loader; validation/protected images and annotation files were not opened.

`failure_causes.csv` contains all 1,400 invalid images, including their matched control IDs, decisions, tier-content comparisons, gap survival, geometry limitations and reasons. `diagnosis_counts.json` records image and distinct-parent counts, the 24 valid reviews, input hashes and the limited pixel checks. Counts below count each parent once within a stated condition; clean/illumination variants are not independent observations. Category parent sets are disjoint, but counts of different mechanisms within a category can overlap.

The diagnosis compares raster-display content after trimming blank canvas margins, preserving internal spaces. These comparisons are offline evidence comparisons, not invented invalid-image CTC targets, CER or transcription accuracy. A mismatch of an entire tier does not locate every character error or establish OCR as the sole cause.

## Ranked causes

1. **F1 lacks aligned count/run validation at its runtime input.** R1 accepts 430 invalid-count-order images / 215 parents and 428 missing-count images / 214 parents (858 / 429 combined). In 423 count-order images / 212 parents and 116 missing-count images / 58 parents, the entire affected tier survives OCR exactly after edge trimming. In 401 / 201 and 110 / 55 respectively, the *entire displayed page* survives. Thus at least 511 accepted invalid images / 256 parents cannot be explained by OCR transcription loss. The original `validate_tiers` intentionally checks character membership and tier presence, marks `alignment_verified=False`, and strips spaces from the membership test. It never invokes the existing strict `validate_aligned_row` for independently cropped OCR tiers. Reversed count tokens contain legal count characters, so F1 accepts them. This is an observable-validation coverage/integration limitation, not a newly discovered Talim rule.

2. **E1's output loses distinctions that structural checks would need.** All 38 accepted wrong-tier images / 19 parents have an affected-tier mismatch and valid-looking glyph membership. Their moved source symbols are D (16 images), U (10), F (8), A (2), T (2). The unchanged count tier matches both the image display and matched control in all 38. Example `v2p_2b95f81713e613befddece0b_wrong_tier`: displayed lower-tier D becomes `_`. In 214 accepted missing-count images / 107 parents, the count prediction equals the displayed count line with internal blanks removed and differs from the actual displayed line. Example `v2p_019d5d64a15fdc4a559d6c0c_missing_count`: `jajifka aa` becomes `jajifkaaa`. Another 98 accepted missing-count images and 7 accepted count-order images have other affected-count-tier differences; their precise local error attribution is unresolved. No F1 count default or missing-count reconstruction exists in the inspected code. The loss occurs in the observed D1/E1 representation before F1, not a F1 default.

3. **No independent image-level semantic invalidity reaches F1.** All 2,800 development results have zero definitive rejections. F1 v2 deliberately limits independent REJECT evidence to `unreadable` / `no_ink`; these semantic negative fixtures are readable. OCR-only syntax violations are routed to REVIEW. High raw CTC/geomean/margin scores are uncalibrated and cannot turn OCR into independent image evidence. D1 tier-role confidence establishes vertical role assignment, not glyph identity, count boundaries or count completeness. This conservative policy prevents false definitive rejection on valid controls and must remain.

4. **D1 uncertainty is real but does not explain most unsafe acceptance.** All 896 accepted invalid images have accepted D1 proposals. Their nominal mutation-cell anchor lies in the saved role crop in 892 cases; five have perspective transforms, so source-coordinate comparisons are not a preservation oracle. Four outside-crop nominal checks and all transformed cases need localization before any D1 blame. D1 returned no safe proposal for 18 invalid images / 9 parents and 12 valid images / 6 parents. A successful D1 proposal does not prove component preservation. We did not regenerate D1 output or transformed pixels; exact component-level attribution outside the sampled cases remains unresolved.

## Matched pairs and image evidence

Across all 1,400 invalid/control variant pairs, only 8 invalid images / 4 parents have identical *complete decoded rows* to their controls, both before and after T1. All eight are missing-count REVIEW cases with unavailable/empty OCR following segmentation failure. Thus there is no confirmed successfully recognized accepted pair with completely identical OCR. This does **not** imply recoverable character-to-image alignment: no character positions or run boundaries are saved, only tier boxes, strings and aggregate scores.

No accepted count-order case has a count-tier prediction identical to its valid control. Count order survives intact at the affected-tier level in 423/430 accepted cases. Example `v2p_0065af0e59d893a535fa824d_invalid_count_token`: displayed `hsncrdca` is recognized as `hsncrdca`, including the reversed `hs` rather than canonical original `sh`. Neither the adapter nor F1 sorts it. But a bare count sequence can be tokenized differently across multiple runs; glyph order alone cannot establish the intended token boundary.

For missing-count cases, an internal count gap survives in 114 images / 57 parents: 108 ACCEPT / 54 parents and 6 REVIEW / 3 parents. No valid image has such a predicted gap in the saved run. This count is a diagnosis of existing observations, not a measured R2 outcome or a threshold selection. Edge trimming and omitted OCR spaces prevent safe recovery of leading/trailing absent counts. Do not infer a missing count from a shortened count string alone.

Five representative clean development pairs (10 distinct image files) were opened, hash checked and visually inspected in `representative_pairs.png`. Their source pixel differences are nonzero, and changed pixels occur inside the saved affected-tier crop in every sampled pair; none has a perspective transform. The inspected examples include:

- `v2p_68beea701e9b9af01fbb2032_wrong_tier`: a glyph visibly moves from upper to lower; the changed lower-tier pixels survive the crop. Recognition differs from the actual displayed notation.
- `v2p_28e3d898ee0000cfac2dcc39_invalid_count_token`: visibly reversed count order, affected count tier preserved by OCR, accepted by F1.
- `v2p_4d44991f24bb82b42c93d9bc_invalid_count_token`: visible reversal survives the crop, but affected-tier OCR also has differences; exact local normalization is not proven.
- `v2p_9452e95e2c128e957edead94_missing_count`: the leading count is visibly absent while its symbol remains; the affected count tier is recognized after margin trimming. Source alignment is needed to establish the absence.
- `v2p_8a19aa6c3ec8ffc04b1bd6c2_missing_count`: count deletion is visible and remains within the tier crop, but OCR does not preserve the complete affected tier.

For the remaining images, image-level validity is supported by existing construction verification (`AUTO_VERIFIED`, no legal canonical raster interpretation, changed pixels, matched valid control, raw-display agreement), not a fresh pixel audit or human expert review. Do not extrapolate the five direct crop checks into proof of universal D1 preservation.

## Reviews, T1 and zero rejection

R1 invalid reviews: 504 images / 252 parents. Of these, 486 / 243 have OCR wrong-tier/unsupported-glyph findings; 18 / 9 have D1 uncertainty. Wrong-tier category: 452 OCR reviews plus 8 D1 reviews. Count-order: 14 OCR reviews. Missing-count: 20 OCR reviews plus 10 D1 reviews.

R1 valid reviews: 24 images / 13 parents. Twelve / 7 have wrong-tier OCR predictions, and 12 / 6 have D1 uncertainty. Example `v2p_1c52fd5a10d946a365c3f185_valid`: legal lower `_` is recognized as upper-only `L`. Example `v2p_3e8b4a866318c10380e5c1aa_valid`: legal `I` is recognized as backslash. Converting all glyph reviews to REJECT would falsely reject these valid controls. Across wrong-tier negatives, 446 / 223 retain the whole affected tier, but the runtime cannot distinguish correct recognition from these control errors with independent image evidence.

T1 changes 12 valid and 12 invalid images from REVIEW to ACCEPT. Its 36 edits comprise 18 confirmed correct on valid references, zero confirmed incorrect, and 18 unscorable on invalid images. The inspected invalid correction is X->B in an upper tier of a missing-count image; it fixes a separate visual alias while leaving the missing-count defect undetected. Existing T1 role/font gates remain unchanged. This explains why syntax disambiguation improves valid acceptance and also exposes 12 more unsafe accepts. B/X is not the explanation for all wrong-tier false accepts; the 38 affected original glyphs listed above contain neither B nor X. No global B/X substitution or automatic reversal of T1 is justified.

## Smallest justified R2

Implemented `r2_structural.py`: preserve the saved R1 decision, and add an OCR-only REVIEW finding for an internal blank in a decoded count line. The existing canonical `encode_count`/`canonical_row` produce contiguous counts for trusted one-character symbols; this adds no grammar rule. It never infers which count is absent, reconstructs a count, changes transcription, or promotes a review to rejection. Existing input-artifact REJECT decisions remain REJECT. No confidence thresholds, image templates, generator/grid information, labels, pairing or expected outcomes enter this runtime guard.

`evaluate_r2.py` reuses completed R0/R1 artifacts and the same immutable raw observations, the existing dataset loader and metrics. It verifies lineage and emits three-way counts, category groups, false rejects/unsafe accepts, parent macro/worst cases, and R2 transitions/regressions against both baselines. Reduced unsafe acceptance and new definitive rejection are separate fields. It does not load D1/E1 or repeat T1 decoding. A small preservation lock covers existing workspace files; the original experiment lock is not rewritten.

**No broader safe rejection heuristic was implemented.** Count-order validation and absent edge counts need observed symbol/count positions and independent glyph/absence evidence. D1 tier boxes plus OCR character indices cannot supply these. A future image-level alignment pass could make the existing aligned validator usable, but requires a separately reviewed design that handles aliases, unknown glyphs, transforms and real images without relying on generator layout. Reusing the dataset inverse renderer as a runtime oracle would violate the requested constraints. Current R2 needs no new image-level pass and introduces no new definitive semantic rejection capability.
